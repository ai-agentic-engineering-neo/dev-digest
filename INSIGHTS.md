## Tool & Library Notes

- 2026-11-20 · testcontainers + OrbStack · *.it.test.ts fail with 'Could not find a working container runtime strategy' while `docker info` works, because the default context socket /var/run/docker.sock is absent under OrbStack → run with DOCKER_HOST=unix://$HOME/.orbstack/run/docker.sock TESTCONTAINERS_RYUK_DISABLED=true, because testcontainers reads DOCKER_HOST, not the active docker context · server/test/helpers/pg.ts, reviews.it.test.ts run
- 2026-11-24 · node:test on Node 24 · 'node --test <dir>' treats the directory as a module and fails with MODULE_NOT_FOUND (reported as 1 failing test, not a usage error), so the .mjs tests of our .claude skill scripts look broken when they are not → pass a quoted glob: node --test '.claude/skills/<skill>/test/*.test.mjs', because Node 21+ resolves test-file globs itself and no longer scans a bare directory argument · .claude/skills/pr-self-review/test/collect.test.mjs run
- 2026-11-24 · macOS tmpdir + git · os.tmpdir() is /var/folders/… but /var is a symlink to /private/var, and 'git rev-parse --show-toplevel' returns the realpath, so a test that compares a fixture repo path from mkdtemp with a path derived from git output gets '../../../private/var/…' mismatches → compare basenames or fs.realpathSync() the mkdtemp result first, because only the realpath side changes · .claude/skills/pr-self-review/test/checks.test.mjs package-gates test
- 2026-11-24 · git worktree + node_modules symlink · a symlinked node_modules (ln -s ../main/client/node_modules) shows up as UNTRACKED in the worktree, because the '.gitignore' pattern 'node_modules/' (trailing slash) matches directories only and a symlink is a file to git, so diff-based tools (pr-self-review collect) review it → create a real node_modules dir and symlink its entries (incl. .pnpm and .bin) one by one, because then the ignored directory hides them · scratchpad worktree for the pr-self-review end-to-end run
- 2026-11-24 · testing PreToolUse Bash hooks live · a hook sees the whole command string, but the shell short-circuits, so 'true || gh pr create --fill' exercises a gate on a dangerous command without ever running it → probe Bash gates this way (never with a real gh/git push, never relying on --dry-run flags that older CLIs lack), because if the hook is not loaded yet the command itself stays harmless · pr-gate.mjs live check in the P4 session
- 2026-11-24 · validating workflow YAML locally · there is no actionlint and no PyYAML on this machine, but reviewer-core/node_modules (and client) ship js-yaml → NODE_PATH=reviewer-core/node_modules node -e 'require("js-yaml").load(…)' to parse .github/workflows/*.yml and assert triggers/needs/outputs before pushing, because the first real PR is otherwise the first parse · P5 workflow check

## Recurring Errors & Fixes

- 2026-11-20 · dev.sh + pnpm ≥11 · ERR_PNPM_VERIFY_DEPS_BEFORE_RUN on client 'pnpm dev': pnpm ≥11 no longer reads the "pnpm" field (client/package.json pnpm.overrides) → run the client with 'npx -y pnpm@10 dev' or move overrides into client/pnpm-workspace.yaml, because pnpm 12 refuses to start rather than silently dropping the overrides · client/package.json, scripts/dev.sh
- 2026-11-20 · dev.sh + Docker · if the first 'docker compose up' fails on a port conflict (5432 taken by another project's Postgres), the devdigest-postgres container stays 'created'; the next dev.sh run does 'docker start' on it → healthy but with NO port mapping, and migrations fail ECONNREFUSED → free the port, then 'docker compose up -d --force-recreate' (keeps the volume; never 'down -v'), because the port binding is fixed at creation time · scripts/dev.sh Postgres section, 'docker port devdigest-postgres'
- 2026-11-24 · PR gate · 'gh pr create' (or 'git push' on a branch with an open PR) is refused by the PreToolUse hook with 'needs a PASS verdict for the current diff', even right after a review, whenever ANY tracked or untracked file changed since that review (the verdict is keyed by the exact diff hash) or the review used another --base → re-run /pr-self-review on the final tree as the very last step before opening the PR, and set PR_SELF_REVIEW_BASE in Claude Code's env for a non-main base, because the hook recomputes the hash against origin/main every time · .claude/skills/pr-self-review/hooks/pr-gate.mjs, .claude/settings.json
- 2026-11-24 · optional git pre-push gate · with install-git-hook.mjs installed, a push to a branch with an open PR is refused ('no pr-self-review verdict') even right after a PASS when the review ran with uncommitted or untracked files, because the git hook hashes the PUSHED COMMIT (diffHashForCommit) while the review hashed the working tree, and they are equal only for a clean tree → commit (or stash) everything first, then run /pr-self-review on the clean tree, then push; the Claude PreToolUse gate alone would accept the dirty-tree review, the git hook will not · .claude/skills/pr-self-review/hooks/git-pre-push.mjs, scripts/collect.mjs diffHashForCommit
