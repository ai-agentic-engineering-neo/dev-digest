# CLAUDE.md

**DevDigest** — local-first AI pull-request review. This repo is the *course starter*: it imports a PR and runs an agent review on it end to end. Later lessons add one feature each.

## Stack

Node ≥ 22 · pnpm ≥ 10 · TypeScript (ESM) · Fastify · Drizzle ORM + Postgres/pgvector · Next.js App Router + React · TanStack Query · Zod · vitest · Docker (Postgres only — API and web run on the host).

## Commands

```sh
./scripts/dev.sh     # Postgres + API :3001 + web :3000   (--no-seed · --no-client · --db-only)
./scripts/e2e.sh     # isolated seeded stack on :5433/:3101/:3100 → e2e flows → teardown
docker compose up -d # Postgres only
```

Per package: `pnpm dev` · `pnpm build` · `pnpm test` · `pnpm typecheck`.
Server also: `pnpm db:migrate` · `pnpm db:seed` · `pnpm db:generate`.

## Non-default conventions

- **Not a monorepo.** No workspace, no shared lockfile — each package installs its own deps. Cross-package imports resolve through tsconfig `paths` (`@devdigest/shared`, `@devdigest/reviewer-core`, `@devdigest/ui`) straight to **TypeScript source**; nothing is built or published between packages.
- `@devdigest/shared` is **vendored twice** (`server/src/vendor/shared`, `client/src/vendor/shared`).
- One Zod schema per contract is the request validator, the response serializer, the client's type, *and* the LLM's JSON Schema. Extend contracts with new files; don't rewrite existing ones.
- Server tests split by filename: `*.it.test.ts` is DB-backed (testcontainers Postgres), everything else must be hermetic.

## Gotchas

- Migrations are **not** applied on boot. After a pull: `cd server && pnpm db:migrate`. `relation ... does not exist` always means this step was skipped.
- The two vendored `shared` copies **have already drifted** (server is ahead). Changing a contract both sides use means editing both.
- `docker compose down -v` destroys the `devdigest_pgdata` volume and every imported repo/review. For a clean DB use `./scripts/e2e.sh`, which is isolated.
- The app boots with **zero** API keys. Secrets live in `~/.devdigest/secrets.json` (mode `0600`) or env — never in the DB, never in git.
- e2e flows `02/04/05` assume the seeded demo repo is the *only* repo, so they fail against a dev DB with real imports.

## Do not touch

- `server/src/db/migrations/**` — applied migrations and `meta/_journal.json` are append-only. Add a migration with `pnpm db:generate`, never edit an old one.
- `client/src/vendor/ui/**` — vendored design system. Extend through its barrel; don't restructure it.
- `server/clones/**`, `client/.next/**`, `**/test-results/**` — runtime artifacts, git-ignored.
- `skills-lock.json` hashes — regenerated by tooling, not hand-edited.
- **Lesson scaffolding**: unused DB tables, shared contracts, and i18n namespaces exist for lessons L02–L08. Leave them empty rather than deleting them.
