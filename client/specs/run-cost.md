# Spec: Run cost on three screens

Status: implemented on branch `claude/project-thread-sl61oc` · 2026-11-28
Owner modules: `server/` (data), `client/` (UI). Lab: L01, task 3 "Run Cost Badge".

## Problem

A reviewer run costs money (LLM tokens), but the UI only shows the latest run
cost as a small badge next to the PR number and in the trace "Stats" block. The
design asks for cost on three screens so a reviewer can see what each run cost
without opening logs.

## Acceptance criteria

1. **PR list** (`/repos/:repoId/pulls`) has a dedicated **COST** column. It shows
   the USD cost of the PR's latest completed review run, compact (`$0.012`).
   A PR with no completed run shows `—`, never `$0.00`.
2. **Review run header** on the PR page (`ReviewRunAccordion`) shows the run's
   cost and tokens next to the time it ran: `$0.014 · 8.2K→1.3K`. A run without
   recorded usage shows no cost (no fake price).
3. **Agent Run sidebar** (`RunTraceDrawer` → Stats: Duration / Tokens / Findings)
   has a **Cost** stat. Unknown cost renders `—`.
4. Numbers are readable: at least 2 significant digits below one cent
   (`$0.0017`, `$0.012`), never `$0.00`.
5. A failed, cancelled or still-running run never shows a price.
6. Zero additional model calls: cost comes from data reviewer-core already
   returns (`costUsd`, summed over all model calls; real OpenRouter
   `usage.cost` when available, price-book estimate otherwise).

## Decisions

- **Which run in the PR list?** The latest review (newest `agent_runs` row
  with `status = 'done'`). With "Run all agents" each agent is its own run, so
  the column shows the last agent's run, not the batch sum.
- **Where is cost stored?** A new nullable column `agent_runs.cost_usd`
  (`double precision`), written by `completeAgentRun`. Chosen over reading
  `run_traces.trace -> 'stats' ->> 'cost_usd'` because:
  - cost is a first-class run metric like `tokens_in` / `duration_ms`, and
    every list endpoint can select it without touching the large trace jsonb;
  - it can be aggregated/indexed later (L08 metrics) with plain SQL.
  Trade-off: one new migration (generated by `pnpm db:generate`, existing
  migrations untouched). The migration backfills the column from
  `run_traces.trace.stats.cost_usd` for runs recorded before it existed; runs
  older than that fall back to a price-book estimate from tokens.
- The trace keeps `stats.cost_usd` too (the drawer reads the trace document).

## API changes (snake_case)

| Endpoint | Field | Notes |
|---|---|---|
| `GET /repos/:id/pulls` | `PrMeta.last_run_cost_usd` (existing) | now read from `agent_runs.cost_usd` |
| `GET /pulls/:id/reviews` | `ReviewRecord.cost_usd`, `tokens_in`, `tokens_out` | joined from the review's `agent_runs` row; `null` when unknown |
| `GET /pulls/:id/runs` | `RunSummary.cost_usd` | `null` for failed/cancelled/running |

Both vendored contract copies (`server/src/vendor/shared`, `client/src/vendor/shared`) change.

## UI components (matched to `DevDigest Design (standalone).html`)

| Screen | Component | Design |
|---|---|---|
| shared | `client/src/components/run-cost-badge/RunCostBadge` | variants `cell`, `cost`, `usage`, `tokTotal` |
| PR list | `pulls/_components/PRRow` + `GRID` / `COLUMN_KEYS` | COST column between STATUS and UPDATED, plain mono `$0.014`, `–` when none |
| PR page · timeline | `[number]/_components/RunHistory` | under the run time: `9,119 tok · $0.0013` (done runs only) |
| PR page · review run header | `[number]/_components/ReviewRunAccordion` | `score · $0.001 · date`: cost alone before the time |
| PR page · verdict banner | `[number]/_components/VerdictBanner` | under PR SCORE: `$ $0.014  8.2K→1.3K` |
| Agent Run sidebar | `RunTraceDrawer/_components/TraceBody` | Stats order DURATION · TOKENS · COST · FINDINGS; unknown → `—` |

Not in scope (present in the design, not part of the cost feature): FINDINGS column
and per-row "Run Review" button on the PR list, "trace" link in the run header.
