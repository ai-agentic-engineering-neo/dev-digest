# CLAUDE.md

Map for agents working in this repo. Not documentation — see [README.md](README.md)
and [TESTING.md](TESTING.md) for depth; this file only points and warns.

## What this is

Local-first AI PR-review tool. Diff → prompt → LLM → citation-checked findings → UI.

Each package below also has its own `CLAUDE.md`, auto-loaded when you touch a
file inside it — module-specific conventions/gotchas live there, not here.

## Structure (4 standalone packages, no workspace — separate lockfiles/node_modules)

| Path | Package | Role |
|---|---|---|
| `server/` | `@devdigest/api` | Fastify API: DB, GitHub sync, review orchestration, `repo-intel` indexer |
| `client/` | `@devdigest/web` | Next.js UI |
| `reviewer-core/` | `@devdigest/reviewer-core` | Pure review engine (diff→prompt→LLM→grounded findings). No DB/GitHub/FS — consumed as TS source via path alias, not built to JS. |
| `e2e/` | `@devdigest/e2e` | Deterministic browser e2e, no LLM |
| `server/src/vendor/shared` | `@devdigest/shared` | Zod contracts shared by all packages — lives under `server/` but is not server-private |

Cross-package imports = tsconfig path aliases, not npm links.

## Stack

- `server`: TS/ESM, Fastify 5, Drizzle ORM + Postgres/pgvector, Zod, Octokit, `openai`/`@anthropic-ai/sdk`, `tsx`/vitest
- `client`: TS, Next.js 15 (App Router), React 19, Tailwind 4, `@tanstack/react-query`, `next-intl`, vitest + RTL
- `reviewer-core`: TS, no framework — `openai` SDK + Zod only
- `e2e`: TS + `tsx`, driven by agent-browser (CDP)

## Run

```sh
./scripts/dev.sh              # Docker Postgres + install + migrate + seed + both dev servers
```
Manual steps and flags: see [README.md](README.md#quick-start-from-zero).
`server`/`client` use **pnpm**; `reviewer-core`/`e2e` use **npm**. Node ≥ 22.

## Test / typecheck

**No linter is configured** (no ESLint/Prettier anywhere) — typecheck + tests are the gate.

```sh
cd client && pnpm test && pnpm typecheck
cd server && pnpm exec vitest run --exclude '**/*.it.test.ts'   # unit, no Docker
cd server && pnpm exec vitest run .it.test                      # integration, needs Docker
cd server && pnpm typecheck
cd reviewer-core && npm test && npm run typecheck
cd e2e && npm test   # needs the full stack running + agent-browser installed
```
Full strategy: [TESTING.md](TESTING.md). Key rule: DB-backed tests **must** be named `*.it.test.ts`.

## Non-default conventions

- Server module files are named by **role**, not feature: `routes.ts`, `service.ts`,
  `repository.ts`, `helpers.ts`, `constants.ts` inside `server/src/modules/<name>/`.
- Drizzle schema files (`server/src/db/schema/*.ts`): kebab-case, one per domain.
  Columns are `camelCase` in TS, mapped to `snake_case` in Postgres.
- Route-scoped React components live in `_components/<PascalCaseName>/` (Next.js
  private-folder convention) with `<Name>.tsx` + optional `.test.tsx`/`helpers.ts`/`styles.ts`.
  Generic/shared components under `client/src/components/` are kebab-case instead.
- Client hooks: one file per domain in `client/src/lib/hooks/` (`agents.ts`, `reviews.ts`...).

## Gotchas

- Migrations do **not** run on server boot — `pnpm db:migrate` is a separate manual step.
- On Windows, `import.meta.url === \`file://${process.argv[1]}\`` CLI-entrypoint checks
  silently fail (path slash mismatch) — use `fileURLToPath(import.meta.url) === process.argv[1]`.
- `pgvector` extension must exist before vector-column tables — `migrate.ts` creates it.

## Do not touch

- **`server/src/db/migrations/**`** (incl. `meta/`) — generated by `drizzle-kit generate`,
  numbered sequentially, immutable once applied anywhere. Change the schema instead and
  regenerate a new migration.
- **Lock files** (`server/pnpm-lock.yaml`, `client/pnpm-lock.yaml`,
  `reviewer-core/package-lock.json`, `e2e/package-lock.json`) — only the package manager
  should touch these, never hand-edit.
