# `@devdigest/api` — the engine (Fastify + Postgres)

Imports repos/PRs, indexes with `repo-intel`, runs `reviewer-core`. Adapters
(LLM, GitHub, git, ast-grep) sit behind a DI container so tests can swap mocks.

## Stack

Fastify 5.2 (`@fastify/helmet`, `@fastify/cors`, `@fastify/rate-limit`,
`fastify-sse-v2`) · Drizzle ORM 0.38 + drizzle-kit over `postgres` (pgvector) ·
`fastify-type-provider-zod` (Zod schemas double as route validation +
serialization) · `@anthropic-ai/sdk`, `openai`, `octokit`, `@ast-grep/napi`,
`simple-git`, `js-tiktoken`, `graphology` · TypeScript. Test: vitest +
testcontainers-postgresql.

## Commands

`pnpm dev` (:3001) · `pnpm db:migrate` · `pnpm db:seed` · `pnpm db:generate` · `pnpm test` · `pnpm typecheck`.
Unit/integration split: `pnpm exec vitest run --exclude '**/*.it.test.ts'` (unit) / `pnpm exec vitest run .it.test` (integration, needs Docker).

## Naming conventions

- Each feature lives in `src/modules/<kebab-name>/` with fixed file roles: `routes.ts` (HTTP), `service.ts` (business logic), `repository.ts` (DB access), plus optional `helpers.ts`/`constants.ts` — keep new modules to this shape.
- Integration tests must end in `.it.test.ts`; anything else in the suite is treated as hermetic unit (see `../TESTING.md`).
- Migration files: `NNNN_description.sql`, sequential and zero-padded, generated only via `pnpm db:generate` — see Do not touch below.

## Gotchas

- Routes are schema-first (zod via `fastify-type-provider-zod`): invalid input 422s **before** the handler runs — don't hand-roll `Schema.parse(req.body)`.
- Adapters go behind the DI container (`platform/container.ts`) so tests can mock them; see `src/adapters/mocks.ts`.
- Global rate limit is 120/min (disabled under `NODE_ENV=test`); SSE and `/health*` are exempt.
- No keys required to boot — `loadConfig` marks every secret optional; keys can be set at runtime via Settings.

## Do not touch

- `src/db/migrations/*.sql` and `src/db/migrations/meta/` (including `_journal.json`) — generated by `pnpm db:generate`; the journal must stay byte-consistent with the snapshots or Drizzle can't apply migrations (broke once already, see commit `2006964`). To change schema, add a **new** migration via `db:generate` — never edit or delete an existing one.
- `src/vendor/shared` — vendored, shared across packages.
- `clones/**` — git-ignored runtime data.
- `pnpm-lock.yaml` — regenerate via `pnpm install`, never hand-edit.
