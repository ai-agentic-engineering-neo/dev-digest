# Sources: what each one contributed

Researched 2026-11-21. Rationale for the design. You don't need it to run the skill.

| Source | Taken into the skill |
|---|---|
| [MindStudio — Learnings.md + Wrap-Up](https://www.mindstudio.ai/blog/self-learning-ai-skill-system-learnings-md-wrap-up) | The 7 sections; the vague-vs-useful calibration; "don't duplicate, extend"; wrap-up after substantial sessions only; treat output as a draft under review |
| [MindStudio — Learnings loop](https://www.mindstudio.ai/blog/how-to-build-learnings-loop-claude-code-skills) | "Do not overwrite — correct with a dated note" → the `(supersedes …)` rule; the "would a future session change behaviour" test; consolidation at ~80–100 bullets |
| [MindStudio — Learnings.md per skill](https://www.mindstudio.ai/blog/self-learning-claude-code-skill-learnings-md) | "A 30-line file with sharp entries outperforms a 200-line stale one" → cap of 50 per module file; hypotheses kept apart from rules (→ Open Questions). **Rejected:** "MUST update even if nothing new", which contradicts its own no-redundancy rule |
| [MindStudio — Compounding knowledge loop](https://www.mindstudio.ai/blog/compounding-knowledge-loop-claude-code) | Routing knowledge into separate topic files; drop "routine edits, trivial fixes, back-and-forth"; "dump everything" produces noise |
| [MindStudio — Obsidian + hooks](https://www.mindstudio.ai/blog/self-evolving-claude-code-memory-obsidian-hooks) | The Patterns / Mistakes / Decisions / Context categories; "only include what a developer might forget or get wrong again"; a human makes the final pruning decision |
| [MindStudio — Auto-memory](https://www.mindstudio.ai/blog/what-is-claude-code-auto-memory) | Gate criteria: recurrence, not inferable, stability, project-specific; "an incorrect entry propagates across every future session" → the Verified rule |
| [MindStudio — Scripts vs markdown](https://www.mindstudio.ai/blog/claude-code-skills-code-scripts-vs-markdown-instructions) | Deterministic checks go in `scripts/insights.mjs` (stats, lint); judgment stays in prose |
| [MindStudio — Skills vs hooks](https://www.mindstudio.ai/blog/claude-code-skills-vs-hooks-difference) | Skills are invoked by the model and hooks by the system. Automatic triggering would need a hook (deferred) |
| [MindStudio — Context compounding](https://www.mindstudio.ai/blog/claude-code-context-compounding-explained) | Anything read every session costs tokens every session → keep the files short |
| [Aviad Rozenhek — Learn from every mistake](https://dev.to/aviad_rozenhek_cba37e0660/self-improving-ai-one-prompt-that-makes-claude-learn-from-every-mistake-16ek) | "Reflect, abstract, generalize" → generalize one level; NEVER/ALWAYS, lead with why; meta-rules that govern how entries are written |
| [evoleinik — CLAUDE.md as memory](https://dev.to/evoleinik/claudemd-building-persistent-memory-for-ai-coding-agents-5322) | The "saves 5+ minutes next time" test; one line per item; a cap; delete an entry once the bug it works around is fixed; "not a crutch for bad tooling" → fix the root cause first |
| [Anthropic — How we use skills](https://claude.com/blog/lessons-from-building-claude-code-how-we-use-skills) | Skills are folders (scripts, assets, references); the description is written for the model, with trigger phrases; don't state the obvious |
| [Anthropic — Skill best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) | Third-person description ≤1024 chars; SKILL.md <500 lines; references one level deep; a copyable checklist; a validate → fix loop |
| [glebis/claude-skills — retrospective](https://github.com/glebis/claude-skills/tree/main/retrospective) | User corrections rank highest; a gate check (short vs substantial session); ≤5 candidates ranked by signal; read the target before writing, skip duplicates with a note; a one-line summary per action, including skips; never write learnings into the skill file itself |
| [shipyard — lessons-learned](https://github.com/lgbarn/shipyard/blob/main/skills/lessons-learned/SKILL.md) | Capture immediately, because the "why" is lost after ~24h; no line-number references; ≤2 sentences; when *not* to use it (active bugs, design docs) |
| [xtone — lessons (CLAUDE.md Lessons Manager)](https://github.com/xtone/ai_development_tools/blob/main/common_development/skills/lessons-md-manager/SKILL.md) | Signals: user corrections, pivots, build failures, library surprises; "lesson + reason" format; scan the whole conversation; review mode (duplicates, containment, contradictions, vague) applied only after approval |
| [Omega memory](https://glama.ai/mcp/servers/@omega-memory/Omega) | Typed memories (decision / lesson / error); session summaries expire while lessons persist → keep the last 10 Session Notes. `docs/reddit-drafts.md` returned 404, so its real-world report was not available |
| Claude Code docs: [skills](https://code.claude.com/docs/en/skills), [hooks](https://code.claude.com/docs/en/hooks) | The project skill location; a Stop hook can block with a reason, which is the planned path to a guaranteed wrap-up |
