## What Works
<!-- Approaches that proved effective here -->
- 2026-11-04 — To vary data a `vi.mock`-ed hook returns per test, never mutate the module-level fixture (`TRACE.stats.cost_usd = …` / `delete …` made tests order-dependent; flagged by the General Reviewer) → hook reads a `let current = FIXTURE`, a test assigns a spread copy, `afterEach` resets it; verify with `vitest run --sequence.shuffle` (src/app/repos/[repoId]/pulls/[number]/_components/RunTraceDrawer/RunTraceDrawer.test.tsx:24 → currentTrace).
- 2026-11-06 — CORRECTION of 2026-11-06 `--bg-elev` entry: "grep styles.css before using a var" did not hold — 10 more `var(--text)` / `var(--text-dim)` (neither exists; tokens are `--text-primary/-secondary/-muted`) were written in multi-agent styles after it → unknown tokens are now caught by the guard test that scans every `var(--name)` under src/ against declarations in `.css` files (template names like `var(--viz-${n})` are checked by prefix); if it fails, use an existing token — don't add a new one to `styles.css` just to pass (src/test/css-vars.test.ts:46 → "CSS custom properties").
- 2026-11-08 — To test real React Query polling / timeouts in a component, mocking the hook module (`vi.mock("@/lib/hooks/repo-intel")`) can only assert mock arguments, so the resync flow after the click stayed untested → `vi.mock("@/lib/api", importOriginal)` overriding `api.get/post` with a mutable fake server so the REAL hooks run, `QueryClient({ defaultOptions: { queries: { retry: false } } })`, `vi.useFakeTimers({ shouldAdvanceTime: true })` and `await act(() => vi.advanceTimersByTimeAsync(ms))` to fire polls/timeouts; assert what the user sees (src/app/repos/[repoId]/pulls/[number]/_components/OverviewTab/_components/BlastRadiusPanel/BlastRadiusPanel.test.tsx:59 → vi.mock("@/lib/api"), :173 → useFakeTimers).

## What Doesn't Work
<!-- Dead ends and antipatterns — the most valuable section -->
- 2026-11-05 — Closing a hover popover on the trigger's `onMouseLeave` breaks it even when the popover is a DOM child: the 6px gap between cell and popover leaves both, so it vanished before the cursor reached it (DevDigest flagged it, but blamed "not a descendant" — wrong cause) → close after a short delay (`CLOSE_DELAY_MS` 150) that `mouseenter` cancels; blur/Escape close immediately; also cap `maxHeight` to the space in the chosen direction (src/app/repos/[repoId]/pulls/_components/FindingsCell/FindingsCell.tsx:59 → scheduleClose; helpers.ts:24 → placePopover).

## Tool & Library Notes
<!-- Dependency / tooling quirks -->
- 2026-11-04 — On this Windows box `pnpm typecheck`/`pnpm test` fail with "Access is denied" (pnpm 12 shim) → run the bins directly: `node node_modules/typescript/bin/tsc --noEmit -p tsconfig.json`, `node node_modules/vitest/vitest.mjs run` (same in server/) (package.json:10 → scripts.typecheck).
- 2026-11-05 — next-intl `t.rich`: a tag name must not equal a value name (`<repo>{repo}</repo>` collides) — use `<r>{repo}</r>` (messages/en/conventions.json → modal.banner).
- 2026-11-05 — Categorical chart colors live in `--viz-1..6` (styles.css, dark + light steps, validated with the dataviz validator); never reuse status colors (`--crit/--warn/--ok`) for series. `Donut` gained `formatValue` (counts instead of $) and `gap` (src/vendor/ui/charts/Donut.tsx).
- 2026-11-05 — `/pr-self-review` caches findings per file+skill content, so fixing a hook does NOT clear findings cached on its unchanged caller files (`OWN_ERROR_TOAST` highs stayed on the modals after the hooks were fixed); also any `client/INSIGHTS.md` edit invalidates every client pair (~10 agents) → verify such findings against the hook, clear them with `--no-cache`, and finish INSIGHTS edits before the final review (.claude/skills/pr-self-review/scripts/collect-diff.mjs → cache lookup).
- 2026-11-06 — `@testing-library/user-event` is NOT a client dependency (only `@testing-library/react` + `jest-dom`), but the `react-testing-library` skill and plans say `userEvent` → 4 implementers hit TS2307 in one run; use `fireEvent` from `@testing-library/react` (as AgentCard/FindingCard tests do), or add the dep deliberately — never import it ad hoc (package.json:28 → devDependencies).
- 2026-11-06 — jsdom has no `EventSource`, so any test that renders running columns (anything calling `useRunEvents`) crashes → `vi.stubGlobal("EventSource", class { addEventListener() {} close() {} onmessage = null; onerror = null; })` in that test (src/app/repos/[repoId]/multi-agent/_components/MultiAgentView/MultiAgentView.test.tsx:84 → EventSource stub).
- 2026-11-08 — TanStack Query v5 `useMutation({ scope: { id } })` serializes only `mutationFn`; `onMutate` still runs at once for every queued call (query-core 5.101 `Mutation.execute`), so with optimistic updates an EARLIER save's `onSuccess`/`onError`/`onSettled`-invalidate still overwrites the newer optimistic list and the next click computes from stale data → add `mutationKey` + `scope`, and write result / rollback / invalidate the key only when `qc.isMutating({ mutationKey: key, exact: true }) <= 1` (the settling mutation still counts as pending in its own callbacks) (src/lib/hooks/project-context.ts:58 → useSetAgentContextDocs, :62 → isLastSave).
- 2026-11-08 — jsdom never drops focus from a node that React moves on a keyed reorder (browsers do: remove + re-insert blurs it), and for `[a,b]→[b,a]` React keeps `b`'s node and moves `a`'s — so a "focus stays on the moved row's handle" test stayed green with the refocus code commented out → in such tests `el.blur()` before `rerender` with the new order, then assert `toHaveFocus()`, and RED-check by disabling the refocus (src/app/agents/[id]/_components/AgentEditor/_components/ContextTab/ContextTab.test.tsx:161 → "after a keyboard move…"; _components/ContextDocRow/ContextDocRow.tsx:56 → handleRef focus effect).

## Recurring Errors & Fixes

- 2026-11-04 — New UI missing on an already-open PR page although `next dev` had recompiled (`grep countBySeverity .next/static/chunks/app/repos/[repoId]/pulls/[number]/page.js` found it): Fast Refresh didn't patch the stale tab → hard-reload (Ctrl+Shift+R) before debugging code; grep the compiled chunk to tell "not built" from "not reloaded" (src/app/repos/[repoId]/pulls/[number]/_components/FindingsPanel/helpers.ts:26 → countBySeverity).
- 2026-11-05 — `messages/en/prReview.json` repeats key names across namespaces (`filesCount` in `smartDiff` AND `list`; `findings` in `runStatus`, `list.columns`, `list`), so a text edit anchored on a key (first match) put a block into `smartDiff` and the test failed with `MISSING_MESSAGE prReview.list.findings.chip` → anchor on the namespace's unique neighbour key and verify with `node -e "console.log(require('./messages/en/prReview.json').list.findings)"` (messages/en/prReview.json:61, :107 → filesCount).
- 2026-11-05 — Modals rendered at the top of a view come BEFORE the page in the DOM, so `getAllByRole(...)[last]` picks the page button; scope with `within(getByRole("dialog"))` (ConventionsView.test.tsx).
- 2026-11-05 — Skills Lab Config: after Save the editor diffs the form against the `skill` prop taken from the `["skills"]` list cache; with only `invalidateQueries` that prop stays stale until the refetch, so Save re-enabled and a second click stored a duplicate version → in mutations whose result an editor diffs against, `setQueryData` the returned entity BEFORE invalidating (src/lib/hooks/skills.ts:89 → useUpdateSkill onSuccess).
- 2026-11-05 — Skills Lab picks the selected skill as `all.find(id) ?? all[0]` from the `["skills"]` cache, so ANY mutation that adds/removes a skill and then navigates to `?id=` showed a different skill (or kept a deleted one) until the refetch — hit twice (delete, then create/import) → every create/import/delete hook updates `["skills"]` with `setQueryData` before invalidating (src/app/skills/_components/SkillsLab/SkillsLab.tsx:48 → selected; src/lib/hooks/skills.ts:14 → addToSkillList).
- 2026-11-06 — Mock throws "cannot destructure" AFTER a test passed: `beforeEach(() => post.mockReset())` returns the mock, Vitest treats a function returned from a hook as cleanup and calls it with no args → always give `beforeEach` a block body `() => { post.mockReset(); }` (src/lib/hooks/reviews.test.tsx:33 → beforeEach).
- 2026-11-06 — Multi-agent column cards rendered with NO background: styles used `var(--bg-elev)`, which doesn't exist (the token is `--bg-elevated`); an unknown `var()` fails silently and neither tsc nor RTL tests catch it (only /pr-self-review did) → grep `src/vendor/ui/styles.css` for every new `var(--…)` name before using it (src/vendor/ui/styles.css:14 → --bg-elevated; src/app/repos/[repoId]/multi-agent/_components/MultiAgentResults/_components/AgentColumnCard/styles.ts:10 → s.root).
- 2026-11-08 — Blast "Resync index" could end on the FIRST poll before the reindex ran: the `["repo-intel-state", repoId]` cache is not polled while idle, so a baseline `updatedAt` read from it can be stale and any already-advanced value reads as "finished" (index status is terminal-only, completion = `updatedAt` moves) → take the baseline fresh right before the mutation with `qc.fetchQuery({ ...repoIntelStateQuery(repoId), staleTime: 0 })` (src/lib/hooks/repo-intel.ts:41 → repoIntelStateQuery; src/app/repos/[repoId]/pulls/[number]/_components/OverviewTab/_components/BlastRadiusPanel/hooks/useBlastResync.ts:44 → start).
- 2026-11-08 — "Found multiple elements with the role status" in a test wrapped in `<ToastProvider>`: the provider always renders its own `role="status" aria-live="polite"` toast region, so `getByRole("status")` is ambiguous as soon as a component under test also renders a status banner (e.g. `ContextRepoState variant="banner"`) → `getAllByRole("status").find((el) => el.textContent?.includes(<title>))`, or render without ToastProvider when the component doesn't toast (src/lib/toast.tsx:90 → ToastProvider region; src/app/agents/[id]/_components/AgentEditor/_components/ContextTab/ContextTab.test.tsx → "a degraded index shows a banner").
- 2026-11-08 — Context "Resync" stayed busy and polled the doc list for the full 60 s on an already-`ready` repo: completion was `state.status:docs.length`, and a reindex usually changes neither (POST `/repos/:id/resync` only enqueues a job, so the mutation settling means nothing either) → any resync-completion signature must include the index state's `updatedAt` (baseline read fresh via `fetchQuery`, polled alongside) (src/lib/hooks/project-context.ts:112 → signatureOf, :122 → useContextResync).
- 2026-11-08 — Keyboard-reorder refocus kept stealing focus (e.g. from the filter input) while a move was pending: the row's focus effect listed the parent's inline `onHandleFocused` callback as a dep, so it re-ran `focus()` on EVERY parent render until the target position was reached (never, if the save didn't land) → pass `focusHandle` only when the row is AT its target position, and read the callback through a ref so the effect depends on `[focusHandle]` alone (src/app/agents/[id]/_components/AgentEditor/_components/ContextTab/_components/ContextDocRow/ContextDocRow.tsx:60 → focus effect; ContextTab.tsx:169 → focusHandle).
