## Decisions taken by default

- D1 Blob sha comes from `listFiles` (third `ls-tree -l` field, already read) as a new `blob` field per file; no extra git spawn on save.
- D2 (decided by the user, Q2 = A) Overrides apply only to paths that are listed and not `too_large` at the default branch (listing, file read, attachments) or at the run's base branch (runs); otherwise they are ignored and kept. A document whose repository version grows past the size cap after an edit becomes `too_large` and its override is not used.
- D3 (decided by the user, Q3 = A) `DELETE` on an unsafe path → 422; on a path not in the listing → 404, row kept (AC-53); on a listed path without an override → 200 with the repository version.
- D4 `ContextFileUpdate.text` caps the length only; the service rejects empty text with a message pointing to Reset, and text containing NUL, both as 422 `ValidationError` with `issues` (TC-3).
- D5 Override token counts are memoised in the service by `repoId:path:updatedAt`, outside the per-head-sha listing cache, recomputed when `updated_at` changes (AC-51 merges on every call).
- D6 At run time the override replaces the text only when the path is present and under the size cap in the run's base-branch listing (the run's current listing); otherwise the existing skip lines apply. The base branch need not be the default branch (settled spec Q4). The binary check applies to git text only.
- D7 (decided by the user, Q1 = A) AC-69: a `too_large` document shows, in both pills, a notice naming the reason ("This document is larger than 200,000 characters and cannot be opened or edited") instead of the generic preview error; no text.
- D8 The opened document's head gets a `TokenBadge` (from the refreshed listing row), so AC-62's "updated token badge" has a place.
- D9 After a successful save the page stays in Edit mode with the saved text as the new effective text; Preview shows it. Route `bodyLimit` 1,310,720 bytes so the 200,000-character cap, not the 1 MiB app limit, decides.
- D10 Sidebar repository changes go through `requestRepoChange` in `repo-context`; the `/context` page registers a guard while dirty. Leaving the page by other navigation is not guarded (out of scope).
- D11 `client/src/vendor/ui/kit/Textarea.tsx` is not changed: the label is a wrapping `<label>` with visually hidden text, Ctrl/Cmd+S is a window `keydown` listener active only in Edit mode, read-only content keeps today's `<pre>`.
- D12 Save follows AC-60 literally: an empty draft that differs from the effective text enables Save; the server answers 422 and the global toast shows its message (settled spec Q1, edge case "clears the textarea").
- D13 "Modified locally" is one cross-page component (page head and the tabs' Preview modal); the drawer uses a label suffix like "truncated".
- D14 No per-route rate limit on `PUT`/`DELETE` (the global limiter applies; one row per call).
