- 2026-09-22 — src/db/seed.ts + seed-diff.ts: the seed now stores pr_files.patch for PR #482 and a done agent_run linked via reviews.run_id (backfilled only where patch IS NULL / run_id IS NULL, so old DBs get it on re-seed; verified on a throwaway pg16), so the 2026-09-21 'seed leaves patch NULL' entry no longer applies; LLM_PROVIDER_OVERRIDE=mock (adapters/llm/mock.ts, resolved in Container.buildLlm after test overrides) gives a key-free review whose findings ground on that diff → use it for manual/e2e end-to-end checks instead of a fake OpenAI server
- 2026-09-22 — adapters/llm/{openai,anthropic}.ts via adapters/llm/call.ts: reuse reviewer-core's exported createCallBudget/estimateTokens/truncate — one budget signal (caller AbortSignal ∪ deadline) goes to every SDK request with timeout=min(request, remaining), and withRetry retries only while !budget.signal.aborted, bounding SDK retries × withRetry × reprompts; the SDK now receives a COMBINED signal, not the caller's object → tests assert the sent signal aborts when the caller does (test/llm-abort-signal.test.ts), never toEqual({ signal })
- 2026-09-22 — graceful close (app.ts preClose → Container.shutdown): an open GET /runs/:id/events SSE stream keeps app.close() waiting, so preClose cancels live runs (RunBus.cancelAll → executor abort), waits bounded (RunBus.whenIdle 5s ‖ JobRunner.shutdown 10s) and then RunBus.completeAll() ends every stream before onClose closes the pool; verified with SIGTERM on a real tsx server.ts (clean exit) and test/composition.test.ts → keep DB writes of runs/jobs before onClose
- 2026-09-22 — Checking a new migration against real data without touching the dev DB: pg_dump the devdigest-postgres DB into a throwaway pgvector/pgvector:pg16 container on another port, then DATABASE_URL=postgres://…:<port>/devdigest pnpm exec tsx src/db/migrate.ts (the 'relation already exists, skipping' NOTICE it prints is harmless) → use this before shipping constraint/type-changing migrations
- 2026-09-21 — Manual end-to-end check with NO LLM keys and zero spend: OpenAIProvider uses `new OpenAI({ apiKey })`, so the SDK honours OPENAI_BASE_URL → run the API with OPENAI_API_KEY=anything and OPENAI_BASE_URL=http://127.0.0.1:<port>/v1 pointing at a tiny fake /v1/chat/completions server (per-model delay / invalid JSON / usage), and create agents with provider=openai. Without GitHub the diff comes from pr_files.patch, and the seed leaves it NULL → UPDATE pr_files SET patch=… first, or the review sees 0 files

## What Doesn't Work
<!-- dead ends and anti-patterns — the most valuable section -->
- 2026-09-22 — test/*.it.test.ts with buildApp: when overrides.llm is not set, the Container resolves the developer's REAL keys from ~/.devdigest/secrets.json, and a background job (e.g. conventions.extract) makes a real paid LLM call — seen 2026-09-22 as an OpenAI 429 inside a test → always inject overrides.llm (a mock, or a stub that throws ConfigError) for every provider id in tests
- 2026-09-22 — test helpers waitForPrRuns({expected}) on seeded PR #482: returns at once because the seed already has a terminal 'done' run for that PR → in tests on seeded PRs wait on the specific new run id, not on 'all runs terminal'
- 2026-09-22 — server/tsconfig.json include covers only src, and vitest does not typecheck, so a changed port signature breaks test fakes only at runtime (e.g. 'ids.map is not a function'); a tsconfig that also includes test/** shows existing errors too (test/agents-service.test.ts ciFailOn:'major') → after changing a port, grep test/ for its fakes or typecheck with a temp tsconfig including test/**
- 2026-09-22 — test/*.it.test.ts concurrency: Promise.all of N db.transaction() calls on a cold postgres-js pool runs effectively serialized (each tx waits for a new connection), so a lost-update test passed even with SELECT … FOR UPDATE removed (verified 2026-09-22) → warm the pool first (Promise.all of 5× select pg_sleep(0.05)) and prove the test goes red without the lock
- 2026-09-21 — src/modules/pulls/routes.ts under ./scripts/dev.sh (tsx watch src/server.ts): after `git stash` + `git stash pop` of a source file, tsx restarted on the stashed (old) version and never picked up the restored file — even `touch` did not trigger a reload, so the API kept serving old code (new PrMeta fields missing) → after any git op that rewrites files under server/src, restart the dev stack, and curl the endpoint to confirm the change is live

- 2026-09-22 — modules/agents + reviews/application/run-executor.ts (skills are half-wired): skills/skill_versions/agent_skills tables and GET/POST /agents/:id/skills exist, but run-executor never passes skills to reviewPullRequest (trace prompt_assembly.skills is always null), and AgentsRepository.setSkills/linkSkill do not check that skill ids belong to the agent's workspace (unknown id → FK 500, foreign id links silently) and do not bump the agent version → see server/specs/03-skills.md before building on agent_skills
- 2026-09-22 — src/platform/container.ts: Container takes the app logger as an optional 4th ctor arg (buildApp passes app.log) and container.github() hands it to OctokitGitHubClient, resolving the 2026-09-22 'warnings still go to console' note; a bare new Container(config, db) in unit tests still falls back to console → pass a logger there when a test asserts adapter warnings (test/composition.test.ts)
- 2026-09-22 — modules/repo-intel onion layout (Phase 2b-3): the 2026-09-22 indexer entry's pipeline/full.ts + incremental.ts are now application/full-index.ts + incremental-index.ts taking IndexerDeps (ports in application/ports.ts); the reindex transaction is c.transactionRunner((db) => ({ index: new RepoIntelRepository(db) })) and the graph/rank/map savepoint is IndexWriter.savepoint(); parse concurrency is plain forEachBounded (p-queue is a FRAMEWORK for application) → unit-test the indexer with in-memory port fakes plus the REAL astGrepSourceAnalyzer/cloneFileSystem over a tmpdir (test/indexer-pipeline.test.ts)
- 2026-09-22 — modules/reviews onion layout (Phase 2b): container.ts imports reviews/repository.ts and modules/index.ts imports reviews/routes.ts, so those names stay (repository.ts + repository/ = infrastructure, routes.ts + http/ = http); application may not import db/rows even type-only, so use cases work on domain/types.ts shapes (ReviewAgent, ReviewPull) that Drizzle rows satisfy structurally; infrastructure may import only application/ports.ts (depcruise pathNot) → put port interfaces there and 'implements' them in the repository
- 2026-09-22 — modules/<m>/service.ts (onion Phase 2b): .dependency-cruiser.cjs counts p-queue as a FRAMEWORK for the application ring, and the Container exposes no logger → inject bounded concurrency from composition.ts (pulls: runBounded = tasks => new PQueue({concurrency}).addAll(tasks)) and pass req.log into service methods as a request-scoped Logger port; OctokitGitHubClient is built in container.github() without a logger, so its warnings still go to console until container.ts passes one
- 2026-09-22 — .dependency-cruiser.cjs (Phase 2a): every src/modules/<m>/ file is now classified — non-ring names (run-executor.ts, diff-loader.ts, pipeline/*, feature-models.ts) count as APPLICATION, composition.ts/index.ts are exempt; the baseline went 25 → 22 (fixes) → 39 (newly checked files), so the 2026-09-22 'files named otherwise are not checked' entry is resolved → the baseline may only shrink; per-module table in docs/onion-migration.md
- 2026-09-22 — src/http/error-handler.ts: HTTP status comes from AppError.kind via STATUS_BY_KIND (legacy new AppError(code,msg,status) still wins); a ZodError that is NOT request validation (LLM output, stored trace, DB JSON via .parse) is now 500 internal_error, not 422, and unknown routes get the same {error:{code:'not_found'}} envelope → throw platform/errors.ts subclasses and never expect 422 from a service-side parse
- 2026-09-22 — src/platform/container.ts + modules/<m>/composition.ts: module services and job handlers are built ONLY by the module's build<Name>Module(container) factory (listed in modules/composition.ts); container.modules.<m> is lazy and its type is inferred from the factory, and Container.registerJobHandlers() registers every module's jobs at boot (buildApp) → to rewire a module, edit its composition.ts, never container.ts or a routes.ts 'new XxxService'
- 2026-09-22 — platform/sse.ts RunBus is per Container (app.container.runBus), not a module singleton: complete() schedules eviction of all run state after 5 min (unref'd timer, injectable), and publish() after complete only appends to the retained buffer (no emit) so the executor's post-cancel trace keeps its last lines. GET /runs/:id/events for a run the bus no longer holds falls back to the DB: 404 / one final status event / live subscribe if still 'running'
- 2026-09-22 — modules/reviews run lifecycle: the terminal 'done' write sits in ONE transaction with insertReview/insertFindings/markReviewed and is conditional on status='running' (0 rows → throw RunCancelledError → rollback); failAgentRun only moves status from 'running' but still writes usage onto an already-'cancelled' row. Cancel = RunBus.cancel → onCancel aborts the run's AbortController (signal forwarded to every SDK call) → an aborted call ends 'cancelled'. To test the post-checkpoint race, flip agent_runs.status in the DB from inside a mock LLM call (test/run-integrity.it.test.ts)
- 2026-09-22 — modules/repo-intel: the indexer (pipeline/full.ts, incremental.ts) persists a whole reindex inside RepoIntelRepository.transaction(); the depgraph/walk build runs BEFORE it (no outside I/O inside the tx), and incremental's optional graph/rank/map step runs in a nested tx.transaction() = SAVEPOINT so its failure only degrades status to 'partial' → new indexer writes go through the tx-bound repo passed to the callback, never the outer repository
- 2026-09-22 — .dependency-cruiser.cjs: ring rules match modules by file/folder name (service|application, repository|infrastructure, routes|http) — files named otherwise (reviews/run-executor.ts, reviews/diff-loader.ts, settings/feature-models.ts, repo-intel/pipeline/*) are not checked at all, so real layering debt is ~35 edges, not the 25 in the baseline → when moving code, name/place it under a ring folder so depcruise sees it

- 2026-09-22 — src/db/schema + pnpm db:generate (drizzle-kit 0.31): a change that ADDS and DROPS columns on the same table triggers the rename prompt, which fails in a non-TTY shell with 'Interactive prompts require a TTY terminal' → split it: first add the new columns (keep the old ones), generate; then remove the old ones, generate again (0013 + 0014 conventions migrations)

- 2026-09-22 — modules/skills/http/routes.ts (Fastify 5): the default bodyLimit is 1 MiB, so a base64 file upload (skill .zip up to 2 MB) 413s before zod runs → set a route-level bodyLimit on upload routes, not a global one
- 2026-09-22 — modules/skills/infrastructure/repository.ts (Postgres default locale collation): ORDER BY name ignores dashes, so kebab slugs sort differently from JS (n-plus-one-gate vs no-then-chains) → use ORDER BY name COLLATE "C" when a list must match JS/client sorting
- 2026-09-22 — ../biome.jsonc (Biome 2.5.14): a biome.json containing // comments is SILENTLY ignored on auto-discovery — no error, lint just runs recommended defaults (verified 2026-09-22 in a scratch repo; rule overrides stopped applying) — and --config-path=../biome.jsonc from a package dir fails with 'couldn't find an ignore file' because vcs.useIgnoreFile resolves .gitignore from cwd → keep the root config named biome.jsonc and let packages discover it (plain `biome lint .`)
- 2026-09-22 — modules/*/routes.ts response schemas: services return Date objects (IndexState.updatedAt) while @devdigest/shared contracts type timestamps as z.string(); z.string().safeParse(new Date()) fails, so the response serializer 500s → extend the contract for the response (RepoIndexState.extend({ updatedAt: z.union([z.date(), z.string()]) })) — JSON.stringify then emits the ISO string
- 2026-09-22 — fastify-type-provider-zod serializerCompiler: a route 'response' zod schema is applied with safeParse and the RESULT is stringified, so keys missing from the schema are silently stripped and a mismatch (e.g. a DB string outside a shared enum) becomes 500 internal_error via isResponseSerializationError → build response schemas from the @devdigest/shared contract the client types against, and cover each route with an inject test that reads the fields
- 2026-09-22 — modules/*/routes.ts response schemas (fastify-type-provider-zod 4.0.2): the serializerCompiler runs schema.safeParse(data) and serializes result.data (dist/src/core.js), so a response schema APPLIES .default()s, strips unknown keys and 500s on a stale stored value → never use the Settings contract (defaults + z.record(FeatureModelId)) as GET/PUT /settings response; use a non-transforming schema (settings uses z.record(z.unknown()))
- 2026-09-22 — modules/reviews/routes.ts (fastify-type-provider-zod): a POST with no payload reaches the zod body validator as null, not undefined, so body: Schema.default({}) answers 422 → for an optional body use z.preprocess((v) => v ?? {}, Schema)
- 2026-09-22 — src/db/schema (drizzle-orm 0.45 / drizzle-kit 0.31): .nullsNotDistinct() exists only on unique() constraints, not uniqueIndex(); switching generates DROP INDEX + ADD CONSTRAINT … UNIQUE NULLS NOT DISTINCT and ON CONFLICT (cols) still infers it. Query errors are wrapped in DrizzleQueryError, so the pg SQLSTATE (23514/23503/23505) is on err.cause.code, not err.code → read cause first in tests/error translation
- 2026-09-22 — server/package.json pnpm audit: bumping fastify to 5.12.x does not refresh the lockfile's transitive fast-uri/find-my-way (and openai/@anthropic-ai/sdk keep an old form-data), so audit still shows highs → fix with same-major pnpm.overrides in package.json (fast-uri@3, find-my-way@9, form-data@4); remaining dev-only undici highs come from testcontainers 10 and need testcontainers 11
- 2026-09-22 — adapters/git/simple-git.ts (simple-git 3.36): simpleGit({ config: ['http.https://github.com/.extraHeader=Authorization: Basic <b64 x-access-token:PAT>'] }) puts -c before the subcommand, so auth is per-process and never lands in .git/config (a token-in-URL clone persists it in remote.origin.url); simple-git's unsafe-ops plugin blocks credential.helper/core.sshCommand/protocol.allow via -c but allows http.*.extraHeader. GitHub rejects an invalid/expired PAT header even on PUBLIC repos (verified with ls-remote) → a stale stored GITHUB_TOKEN breaks all https clones, not only private ones
- 2026-09-21 — test/*.it.test.ts (Testcontainers): the first run on a machine pulls pgvector/pgvector:pg16 inside beforeAll and hits the 120s hookTimeout, so every test shows as skipped → run `docker pull pgvector/pgvector:pg16` once first. pnpm may be missing on WSL PATH → `npx -y pnpm@10 <cmd>` works without a global install
