## 1. Scope

Мокапи покривають повний Skills Lab (Context / Evals / Stats / Versions / Run on evals, статистика на картках). Письмовий бриф — вужчий: CRUD, редактор тексту, прив’язка до агента, імпорт, нові агенти, контрольний експеримент.

Це **занадто великий** шматок, якщо брати мокапи буквально (ближче до «цілого кабінету», ніж до однієї user story). Якщо лишаємо письмовий бриф і ріжемо зайве з мокапів — це **один just-right спек** з кількома demoable units.

- [ ] (A) Один спек за **письмовими** вимогами. Мокап задає layout (список + редактор як у агентів). Вкладки Context / Evals / Stats / CI, статистика pull%/accept% і community/URL-імпорт — **non-goals** цього спека.
- [ ] (B) Один спек за **повними мокапами** (усі вкладки редактора скіла й агента, статистика карток, Context-прив’язка документів).
- [x] (C) Розбити на кілька спек: (1) CRUD + UI редактора, (2) прив’язка + збірка промпта, (3) імпорт + нові агенти + експеримент.
- [ ] (E) Other (describe)

**Current best-practice context:** Agent Skills spec ([agentskills.io](https://agentskills.io), Claude docs 2026) і OWASP A08 (upload/archive) впливають лише на імпорт; вони не вимагають Evals/Stats у першій поставці.

**Recommended answer(s):** [(A)]

**Why:** Чеклист наприкінці брифа — один демо-прохід. Повні мокапи роздувають спек до окремого кабінету (Evals, Stats, Context). Спліт (C) розірве той самий чеклист між спеками. (A) лишає перевірюваний зріз і явно ріже те, чого бриф не просить.

## 5. Імпорт: формат і джерела

Бриф: markdown **або архів**; продукт дістає **ядро** скіла, показує прев’ю, зберігає лише після підтвердження; виконуване з архіву **не обробляється**. Кнопка «додати»: створити / імпортувати. У i18n уже є file + URL + community.

- [x] (A) Формат [Agent Skills](https://agentskills.io) (2026): `.md` або zip/`.skill`. З архіву читаємо лише `SKILL.md` (YAML frontmatter `name`/`description` + тіло). `scripts/`, `references/`, `assets/` і будь-яке виконуване **ігноруємо**, не розпаковуємо на диск як код і не запускаємо. URL і community — **поза** цим спеком.
- [ ] (B) Лише «сирий» markdown: ім’я з першого heading, без zip.
- [ ] (C) Як (A), плюс імпорт з URL і community catalog (як у поточному `skills.json`).
- [ ] (E) Other (describe)

**Current best-practice context:** Claude/Agent Skills: skill = тека з `SKILL.md` + опційні `scripts/`. Zip має містити теку, не файли в корені. OWASP A08 / upload checklist: MIME + size limit, захист від zip-slip, ніколи не `exec` повантаженого.

**Recommended answer(s):** [(A)]

**Why:** «Архів + ядро + виконуване не запускалось» майже дослівно описує SKILL.md-пакет. URL/community розширюють поверхню атаки (SSRF, чужий контент без файлового підтвердження) і не входять у бриф.

## 6. Довіра після імпорту

На відео: «чужий скіл — це чужі інструкції в промпті агента». Зараз `assemblePrompt` кладе скіли в `## Skills / rules` **без** `<untrusted>` (trusted-ish). Старий i18n каже обгортати імпорт як untrusted data.

- [x] (A) Після підтвердження імпорту скіл зберігається **вимкненим**. Коли користувач увімкнув і прив’язав — тіло йде в промпт як **інструкції** (окремий блок у трасі), не як `<untrusted>` data. На кроці прев’ю — явне попередження про довіру.
- [ ] (B) Імпортоване тіло **завжди** в `<untrusted>` (дані, не інструкції), навіть після enable.
- [ ] (C) Авторські (manual) — інструкції; імпортовані — завжди untrusted data.
- [ ] (E) Other (describe)

**Recommended answer(s):** [(A)]

**Why:** Інакше відео-формулювання бреше: untrusted-обгортка як раз каже моделі **не** слухати ці рядки як інструкції. Disable-until-vet + warning зберігає обережність, не ламаючи сенс скіла.

## 8. Контрольний експеримент — продукт чи демо?

Два сценарії (Test Quality happy-path; API Contract breaking change) і «відкриваємо трасу → блок скілів і додані токени».

- [x] (A) Засіяти **два fixture-PR** (або два фіксовані diff-и) + герметики, що зі скілами промпт містить блок, без скілів — ні. Живий прогон LLM — proof artifact для демо, не CI-гейт (модель недетермінована).
- [ ] (B) Повноцінні eval cases у продукті (вкладка Evals), CI падає, якщо модель не флагує.
- [ ] (C) Лише ручний демо-скрипт у спеку, без сіду PR і без тестів на збірку промпта.
- [ ] (E) Other (describe)

**Recommended answer(s):** [(A)]

**Why:** (B) тягне Evals-модуль. Недетермінований LLM як CI-гейт буде флакати. Збірка промпта й присутність блоку в трасі — детерміновані, їх треба тестувати.
