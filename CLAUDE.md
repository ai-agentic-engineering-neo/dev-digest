# DevDigest — local-first AI PR review

Import a PR, run reviewer agents on it, get grounded structured findings.
Starter template: roadmap milestones M1–M8 add features back (see README.md).

## Stack
Node 22+ · TypeScript 5 (ESM) · Fastify 5 · Drizzle ORM + postgres-js ·
Postgres 16 + pgvector (Docker) · Next.js 15 / React 19 · TanStack Query ·
Zod 3 · Vitest 2. pnpm for `server/` + `client/`, npm for `reviewer-core/` + `e2e/`.

## Commands
- Whole stack: `./scripts/dev.sh` (`--no-seed` · `--no-client` · `--db-only`)
  → web :3000, API :3001, Postgres :5432
- Per package: `typecheck` · `test` (see each package CLAUDE.md)
- Hermetic e2e (own DB, ports 3100/3101/5433): `./scripts/e2e.sh`

## Map
- `server/` — Fastify API, DB, adapters, repo-intel indexer → server/CLAUDE.md
- `client/` — Next.js studio UI → client/CLAUDE.md
- `reviewer-core/` — pure engine: diff → prompt → LLM → grounded findings → reviewer-core/CLAUDE.md
- `e2e/` — deterministic browser flows on seeded data → e2e/CLAUDE.md
- `docs/agent-prompts/` — reviewer system prompts (human-readable originals)
- `specs/` — feature specs, one file per feature (cross-package)
- `.github/workflows/` — one CI workflow per package, path-filtered

## Non-default conventions
- No workspace: each package has its own lockfile; cross-package code is shared
  through tsconfig path aliases, not published modules.
- Zod contracts (`@devdigest/shared`): `server/src/vendor/shared` is canonical;
  `client/src/vendor/shared` is a COPY — a contract change must land in both.
  reviewer-core imports the server copy.
- A feature starts from a spec in `specs/`.

## Insights loop
- After the user's prompt and BEFORE answering or starting work, read the `INSIGHTS.md` of every
  module the request is about or will touch; treat it as high-confidence guidance.
- At the end of a session/task, run /engineering-insights. It writes only insights that are
  significant AND not already in the file; if nothing qualifies, it writes nothing.
- Promote insights that became stable rules to that package's Gotchas.

## Gotchas
- Only Postgres runs in Docker; API and web run on the host.
- The DB schema already has every table for M1–M8; unused ones sit empty.
- Seed demo data (`acme/payments-api`, PR #482) is fake — no GitHub repo behind it.
- Keys from the Settings UI go to `~/.devdigest/secrets.json` and override `.env`.
  Only OpenRouter (default agent provider) + GitHub are needed to run reviews.
- Never `docker compose down -v` — it deletes the dev DB volume with real data.

## Do not touch without asking
- Security hardening: git env/config allowlists (`server/src/adapters/git/simple-git.ts`),
  Host check + loopback binding, `INJECTION_GUARD` (`reviewer-core/src/prompt.ts`).
- `server/src/db/migrations/` — generated by drizzle-kit, never hand-edited.
