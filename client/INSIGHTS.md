## What Doesn't Work

- [2026-09-25] Sending `content-type: application/json` on a body-less POST or PUT. Fastify rejects it with "Body cannot be empty". `apiFetch` sets the header only when a body exists. Evidence: `client/src/lib/api.ts:30`.
- [2026-09-25] Editing `src/vendor/shared` directly. It is a copy of `server/src/vendor/shared` and has already drifted; edit the server copy and sync. Evidence: `client/src/vendor/shared/index.ts`.
- [2026-09-25] Rendering a hover popover with `position: absolute` inside a PR-list row: the table card (`s.tableCard`) has `overflow: hidden` and clips it to a thin strip. Anchor it with `position: fixed` from the cell's `getBoundingClientRect()` instead. Evidence: `client/src/app/repos/[repoId]/pulls/_components/PRRow/PRRow.tsx:findingsAnchor`.
- [2026-09-25] pr-self-review's gate hook greps every Bash command for the literal tokens `git push` / `gh pr create`, including inside quoted strings or heredocs; writing those words into a report from a shell command trips the gate. Reword the text or write it with the Write tool. Evidence: `.claude/skills/pr-self-review/scripts/gate.sh:15`.
- [2026-09-26] Importing a runtime value (a Zod enum, a schema) from `@devdigest/shared` in client code breaks the dev server with `Module not found: Can't resolve './contracts/findings.js'`: the barrel uses `.js` specifiers that Next's webpack does not map to `.ts`, and it only gets bundled once something imports a value. Import `type` only; mirror enum values in a local constants file. Evidence: `client/src/app/conventions/_components/CandidateCard/constants.ts`.
- [2026-10-21] Modelling a new Overview card on IntentCard (inner uppercase label row + pill + split badges) diverged from the design, which matched VerdictBanner (icon tile, 18px verdict label, one 'N findings · M blockers' badge, score column) and already carries the SectionLabel above it; the user had to point at the card. A plan row for a card that sits under a SectionLabel must name the component whose layout it mirrors and say the card has no inner title. Evidence: `client/src/app/repos/[repoId]/pulls/[number]/_components/OverviewTab/_components/PrBriefCard/PrBriefCard.tsx:titleRow`.

## Codebase Patterns

- [2026-09-25] Query errors toast only on network failure or 5xx; 4xx stays silent so views render inline empty states. Mutations always toast. Evidence: `client/src/lib/providers.tsx:38`.
- [2026-09-25] Route files are thin; all logic lives in colocated `_components/<Name>/` with `styles.ts`, `constants.ts`, `helpers.ts`, `index.ts`, and `*.test.tsx`. Evidence: `client/src/app/repos/[repoId]/pulls/[number]/_components/`.
- [2026-09-25] Styles are inline `CSSProperties` objects keyed off CSS variables; theme switching is the `data-theme` attribute. Tailwind is installed but the UI kit does not use per-component stylesheets. Evidence: `client/src/lib/theme.tsx:18`.
- [2026-09-25] `/` redirects to the first repo's PR list, so with several repos in the dev DB the landing page is whichever sorts first. Evidence: `client/src/app/page.tsx:17`.
- [2026-09-25] Cost formatting threshold is `0.10`, not `0.01`: two decimals from ten cents up, two significant digits below (`$0.06`, `$0.012`, `$0.0013`). A `0.01` cut-off rendered the design's `$0.012` as `$0.01`. Evidence: `client/src/lib/format-cost.ts:formatCost`.
- [2026-09-25] ESLint runs `eslint-plugin-react-hooks` recommended rules but `react-hooks/set-state-in-effect` is switched off in `eslint.config.mjs`: six existing hydration-safe effects (theme, active repo, editor state, mermaid) set state on mount by design. Rejected: refactoring them to `useSyncExternalStore` just to satisfy lint. Evidence: `client/eslint.config.mjs:set-state-in-effect`.
- [2026-09-25] `src/vendor/ui/nav.ts` was edited (user-approved exception to the do-not-touch rule) to add the SKILLS LAB sidebar section with Skills (`g s`) and Agents; `activeKeyFor` already knew `/skills`. Any further nav change goes there too, not in app-shell. Evidence: `client/src/vendor/ui/nav.ts:SKILLS LAB`.
- [2026-09-26] A statically rendered page whose client component calls `useSearchParams` must wrap it in `<React.Suspense>` in page.tsx, or `next build` fails with a missing-Suspense error; dynamic routes like /agents/[id] do not need it. Evidence: `client/src/app/skills/page.tsx`.
- [2026-09-26] The `Modal` primitive pads its header and footer only; the body is the caller's job (`body: { padding: 24 }` in a colocated styles.ts, as CreateAgentModal does). `Drawer` pads its body itself. A modal whose content touches the edges is missing that wrapper. Evidence: `client/src/vendor/ui/kit/Modal.tsx:60`.
- [2026-10-06] Deep relative imports into src/lib or src/components are an ESLint error (no-restricted-imports regex) since 2026-10-06; 42 older files sit in the frozen LEGACY_DEEP_RELATIVE list. Remove a file from the list when converting it to @/, never add one. Evidence: `client/eslint.config.mjs DEEP_RELATIVE_IMPORT`.
- [2026-10-06] Every mutation error is already toasted by the global MutationCache.onError in client/src/lib/providers.tsx; a component that also renders its own role=alert for that mutation reports the failure twice. Pick one surface, or opt the mutation out of the toast via meta. Evidence: `client/src/lib/providers.tsx MutationCache; OverviewTab/_components/IntentCard/IntentCard.tsx refreshError`.
- [2026-10-12] POST /repos/:id/resync answers 202 and finishes in a background job, and useResyncRepoIntel only invalidates repo-intel-state, so a view that depends on the index (BlastRadiusCard) must remember the index row's updatedAt at click time, poll useRepoIntelStatus(repoId, true) and invalidate its own query when the timestamp advances; found by pr-self-review (the card stayed on its empty state until a reload). Evidence: client/src/app/repos/[repoId]/pulls/[number]/_components/BlastRadiusCard/BlastRadiusCard.tsx:rebuildFrom Evidence: `client/src/app/repos/[repoId]/pulls/[number]/_components/BlastRadiusCard/BlastRadiusCard.tsx:rebuildFrom`.
- [2026-10-20] The sidebar section in vendor/ui/nav.ts and the page breadcrumb are decoupled: each page passes its own crumb strings to AppShell (e.g. context.json page.crumbLab), nothing derives the breadcrumb from the NAV group. Moving a nav entry to another section (Project Context: Skills Lab → Workspace on 2026-10-20) silently leaves the old section name in the breadcrumb unless the page's crumb string is changed too. Evidence: `client/src/app/context/_components/ProjectContextView/ProjectContextView.tsx:crumb`.
- [2026-10-21] Pages that are not under /repos/:id but still depend on the sidebar repo (only /context today) must be special-cased in useShellContext.onSelectRepo: the sidebar RepoSwitcher's only effect is that callback, which stores the id and pushes /repos/:id/pulls, so without the exception a repo pick on such a page navigates away. The page itself just reads useActiveRepo(); the URL stays repo-free and ?doc= is dropped on switch. Added 2026-10-21 when the /context page lost its own selector. Evidence: `client/src/components/app-shell/hooks/useShellContext.ts:onSelectRepo`.
- [2026-10-21] IconBtn (vendor/ui/primitives) has no disabled prop, like Checkbox: to show a design's not-yet-wired icon (Project Context toolbar add/folder/upload, 2026-10-21) wrap it in a span with aria-disabled, opacity and cursor not-allowed, pass no onClick and put '(Not available yet)' in the label; the button itself stays focusable. A proper disabled prop is a design-system task (add to /showcase when done). Evidence: `client/src/app/context/_components/ProjectContextView/ProjectContextView.tsx:PLANNED_TOOLS`.
- [2026-10-21] A page-level veto over the sidebar repository switch is a guard registered in repo-context (useRepoChangeGuard, ref in the provider) and consulted by useShellContext.onSelectRepo through requestRepoChange; the guard receives proceed and runs it only after the user confirms, so the shell never imports page state. Page tests that mock @/lib/repo-context must also export useRepoChangeGuard. Evidence: `client/src/lib/repo-context.tsx:useRepoChangeGuard`.
- [2026-10-21] The shell's <main> is flex:1 with overflow:auto and no padding, so a full-height two-pane page (Project Context's FilePanel + DocPane, 2026-10-21) must set its own frame: the page div uses display:flex, height:100%, minHeight: calc(100vh - 52px) (52px = top bar) and each pane scrolls itself (minHeight:0 + overflow:auto); without minHeight the panes collapse to content height and the panel's border-right stops short of the footer. Pages with a padded card layout (skills, agents) do not need this. Evidence: `client/src/app/context/_components/ProjectContextView/styles.ts:page`.
- [2026-10-21] Master-detail pages (agents/[id], now /skills) keep selection and tab in URL search params written with router.replace, and a route that moved inline (/skills/[id] → /skills?skill=) stays as a server page that calls next/navigation redirect() after awaiting both params and searchParams promises (Next 15), so old links and the create-skill flow keep working. Delete actions move into the editor's Config tab so the list column has no destructive controls. Applied 2026-10-21. Evidence: `client/src/app/skills/[id]/page.tsx`.
- [2026-10-21] A list page that becomes master-detail does not need a new route: /agents keeps AgentsListView only for the loading/error/empty states and router.replace()s to the first /agents/:id, where the column already lives (2026-10-21). Keep the list page's e2e-visible behaviour (wait --url '/agents' still matches '/agents/<id>', and the seeded card text is in the column), and move the create modal one folder up so both pages import it without a deep _components path. Evidence: `client/src/app/agents/_components/AgentsListView/AgentsListView.tsx`.
- [2026-10-21] react-markdown 'components' defined inline in the Markdown primitive was a new element type on every render, so any parent re-render remounted the rendered text (a test's findByText element went stale). Hoisted to a module-level COMPONENTS constant. Evidence: `client/src/vendor/ui/primitives/Markdown.tsx:COMPONENTS`.
- [2026-10-21] RoleGroup and FileCard read their open state once at mount (useState initialiser), so the ?file=&line= deep link opens them through forceOpen effects that only ever set open=true; a controlled open prop was rejected to keep the diff-viewer API minimal.
