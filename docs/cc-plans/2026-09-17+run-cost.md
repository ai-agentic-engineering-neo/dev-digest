# Run Cost — вартість запусків на 4 поверхнях

## Context

Ревʼю-ран коштує реальних грошей, але зараз у студії ніде не видно скільки. Щоб відповісти
«у скільки обійшлося ревʼю цього PR?», треба відкривати дашборд OpenRouter.

Дані **вже є**. `reviewer-core` рахує вартість на кожному ранi:
`OpenRouterProvider.completeStructured` просить `usage: { include: true }`, віддає перевагу
реальному `usage.cost` від OpenRouter, з фолбеком на інʼєктований `estimateCost`
(`server/src/platform/price-book.ts` → `server/src/adapters/llm/pricing.ts`). Значення доходить
до `ReviewOutcome.costUsd` — і **викидається за один рядок до збереження**:

```ts
// server/src/modules/reviews/run-executor.ts:213
const { tokensIn, tokensOut, grounding } = outcome;   // costUsd тут зникає
```

Так сталося навмисно: коміт `d45ab0d` зняв персистенс вартості (міграція `0009` дропнула
`agent_runs.cost_usd`), а `58c6ac7` прибрав рядок usage з таймлайну — щоб цю фічу будував студент.
Прайсинг-рушій лишили цілим. Отже задача — **перестати викидати значення** й показати його.

Нуль додаткових викликів моделі. Вартість не перераховується — береться з того, що ран уже видав.

## Рішення, узгоджені з користувачем

| Питання | Рішення |
|---|---|
| Що показує COST у списку PR | **Сума останнього батчу** — усіх агентів одного натискання Review All |
| Рядок таймлайну | **Токени + cost**: `9,119 tok · $0.0013` |
| VerdictBanner (плашка вердикту) | **Включено** — 4-та поверхня, `$0.014 · 8.2K→1.3K` |

## Scope

| Поверхня | Показує | Компонент |
|---|---|---|
| Список PR — колонка `COST` | `$0.014` (останній батч) | `PRRow` |
| Таймлайн Agent runs — під часом | `9,119 tok · $0.0013` | `RunHistory` |
| Trace drawer — плитка поряд з DURATION/TOKENS/FINDINGS | `COST $0.06` | `TraceBody` |
| Плашка вердикту — під summary | `$0.014 · 8.2K→1.3K` | `VerdictBanner` |

**Поза скоупом:** агрегація по репо/агенту/часу, бюджети й алерти, бекфіл старих ранів
(лишаються `NULL` → `—`), будь-яка зміна способу *обчислення* вартості.

## Два правила, на яких тримається дизайн

**`null` ≠ `$0`.** Невідома вартість (немає завершеного рану; модель відсутня в прайс-буці)
рендериться як `—`. Справді безкоштовний ран — `$0.00`. На стратегії map-reduce `costUsd`
схлопується в `null`, якщо хоч один чанк без ціни (`reviewer-core/src/review/run.ts:184`), тож
різниця несуча.

**Фіксовані десяткові вбивають ці числа.** Реальні рани тут коштують **$0.0004–$0.02**.
Хелпер, видалений у `d45ab0d`, використовував `toFixed(2)` — майже кожен ран ставав `$0.00`.
Тому форматування за **значущими цифрами** (вимога слайда: ≥3 значущі, `$0.012` а не `$0.01`).

## Server

### 1. Схема + міграція

`server/src/db/schema/runs.ts` — дві колонки в `agentRuns`:

```ts
/** USD cost of this run; null when unknown (unpriced model / failed run). */
costUsd: doublePrecision('cost_usd'),
/** Groups the runs of ONE "Review all" invocation (all agents fired together). */
batchId: uuid('batch_id'),
```

Повернути `doublePrecision` до імпорту. Прецедент типу: `ci_runs.cost_usd`, `eval_runs.cost_usd`.

Далі **`pnpm db:generate`** → зʼявиться `0010_*.sql` + `meta/0010_snapshot.json` + запис `idx: 10`
у `_journal.json`. ⚠️ Журнал міграцій **тільки дописувати** — ніколи не перезаписувати
(`server/INSIGHTS.md`, інцидент corruption). Жодних ручних правок у `migrations/`.

`batch_id` замість евристики «рани в межах N секунд»: `ran_at` ставиться на створенні і рани
одного Review All різняться на мілісекунди, але точна межа батчу з часу невиводна. Одна uuid-колонка
робить групування детермінованим. Старі рани мають `batch_id = NULL` → кожен сам собі батч.

### 2. Запис

- `server/src/modules/reviews/service.ts:~115` — у `runReview` згенерувати `const batchId = randomUUID()`
  **один раз перед циклом** і передати в кожен `createAgentRun`. Це єдиний викликач
  (`run.repo.ts:116` — єдиний `insert(t.agentRuns)` у кодовій базі).
- `server/src/modules/reviews/repository/run.repo.ts` — `createAgentRun` приймає `batchId`;
  `completeAgentRun` приймає `costUsd: number | null` і кладе його в `set({...})`;
  `listRunsForPull` мапить `cost_usd: run.costUsd`.
- `server/src/modules/reviews/repository.ts:141,151` — прокинути обидва поля у фасадних сигнатурах.
- `server/src/modules/reviews/run-executor.ts` — 5 точок (всі з реверс-діфа `d45ab0d`):
  - `:213` деструктуризувати `costUsd`;
  - `:243` `completeAgentRun({ …, costUsd })`;
  - `:264` `stats: { …, cost_usd: costUsd }`;
  - `:80` та `:298` (fail-all та catch) → `costUsd: null`;
  - `:421` `traceFromBuffer` → `cost_usd: null`.

  Фейл/скасування пишуть `null`, а не `0` — «незавершений прогін не показує фейкову ціну».

### 4. Агрегат для списку PR

`server/src/modules/pulls/routes.ts:114-130` вже має прецедент — блок latest-review `score`.
Поряд додати другий: один `inArray`-запит по `agent_runs` зі `status='done'`, `orderBy(desc(ranAt))`.

Чисту логіку винести у **новий файл `server/src/modules/pulls/latest-batch-cost.ts`** —
щоб покрити юніт-тестом без БД:

```ts
/** Rows newest-first. Latest DONE run per PR defines the batch; sum that batch. */
export function latestBatchCostByPr(
  rows: { prId: string; batchId: string | null; runId: string; costUsd: number | null }[],
): Map<string, number | null>
```

Правила: ключ батчу = `batchId ?? runId` (старі рани — самі собі батч). Сумуються **відомі**
значення; якщо в батчі жодного відомого → `null`. Рани `running`/`failed`/`cancelled` не входять
зовсім — тому PR, чий найновіший ран ще в польоті, показує вартість **попереднього** завершеного
батчу, а не `—` і не нулі напівготового рану.

## Client

### 5. Спільні форматери — новий `client/src/lib/format.ts`

Спільного модуля форматерів зараз немає, вони локальні й дублюються.

```ts
/** USD cost, significant-digit based. null/undefined → "—". */
export function formatCost(usd: number | null | undefined): string
```
- `null`/`undefined` → `—`
- `0` → `$0.00`
- `< 1` → `toPrecision(3)`, обрізати хвостові нулі, мінімум 2 десяткові
- `>= 1` → `toFixed(2)`

Перевірка на макетах: `$0.014` `$0.041` `$0.003` `$0.028` `$0.012` `$0.022` (список) ·
`$0.0013` `$0.0014` `$0.0012` (таймлайн) · `$0.06` (drawer) — формула відтворює кожне.

```ts
/** "9,119" — thousands-separated token total. */
export function formatTokenCount(n: number): string
```

`formatTokens(in, out)` (`15k→1.2k`) **переїжджає** з
`…/RunTraceDrawer/helpers.ts:23` у `format.ts` без зміни поведінки — щоб drawer і VerdictBanner
писали токени однаково. Імпорт у `TraceBody.tsx` оновити; drawer візуально не змінюється.

### 6. Колонка COST у списку PR

`…/pulls/constants.ts`:
- `COLUMN_KEYS` → `[…, "score", "status", "cost", "updated"]`
- `GRID` → `"1fr 132px 92px 60px 118px 86px 78px"` (новий трек перед `updated`)

### 7. Таймлайн

`…/_components/RunHistory/RunHistory.tsx` — повернути рядок, знятий у `58c6ac7`, у правій
колонці під часом (`:198`, вона вже `flexDirection: "column"` під другий рядок):

### 9. Плашка вердикту

Дані вже на сторінці — `prRuns` є у `FindingsTab` (`:18`) і матчаться по `review.run_id`.
Жодного нового запиту.

- `FindingsTab.tsx:158` → передати в `ReviewRunAccordion` знайдений `RunSummary` (`runs.find(r => r.run_id === review.run_id)`).
- `ReviewRunAccordion.tsx:140` → прокинути `costUsd` / `tokensIn` / `tokensOut` у `VerdictBanner`.
- `VerdictBanner.tsx` — нові опційні пропси; під `summary` рядок `$0.014 · 8.2K→1.3K`,
  **повністю відсутній**, коли `costUsd == null`.

  `0.00039347 → "$0.000393"`, `0.012 → "$0.012"`, `0.06 → "$0.06"`, `1.234 → "$1.23"`,
  `0 → "$0.00"`, `null → "—"`.

- `server/test/contracts.test.ts:157` — повернути `cost_usd` у фікстуру `RunStats`.
- `server/test/reviews.it.test.ts` — після `waitForPrRuns` перевірити, що `cost_usd` персистнуто
  (`server/src/adapters/mocks.ts:85` віддає `costUsd: 0.001`) і що всі рани одного виклику мають
  спільний `batch_id`. Тест піднімає Postgres через testcontainers і проганяє міграції — нова
  міграція перевіряється автоматично; без Docker сьют скіпається чисто.
- Клієнтські тести поповерхнево: `PRRow.test.tsx` *(new)*, плюс `cost_usd` у фікстурах
  `RunHistory.test.tsx:25`, `RunTraceDrawer.test.tsx:10`, `VerdictBanner.test.tsx`.
- `pnpm typecheck` + `pnpm test` у `client/` і `server/`.

**Вручну**

1. `cd server && pnpm db:migrate` — міграції на старті не виконуються.
2. `./scripts/dev.sh`, запустити Review all на будь-якому PR.
3. Список PR показує суму батчу; PR без ревʼю — `—`.
4. На PR: рядок таймлайну `N,NNN tok · $X`, плашка вердикту `$X · N.NK→N.NK`, у drawer плитка `COST`.
5. Ран у польоті / зафейлений — ціни не показує ніде.
6. **Звірка**: цифру одного рану зіставити з логом прогону і з дашбордом OpenRouter.

## Порядок робіт

1. Схема + `pnpm db:generate` + `db:migrate` (окремо, щоб міграція була чистою й одинарною).
2. Server: batchId у service/repo → costUsd у run-executor → контракти (обидві копії) → агрегат + його юніт-тест.
3. Client: `format.ts` + тест → 4 поверхні по одній, кожна зі своїм тестом.
4. `pnpm typecheck && pnpm test` в обох пакетах, потім ручна звірка з OpenRouter.
5. Комітом разом із планом (`docs/cc-plans/2026-09-17+run-cost.md`); на завершення — `/engineering-insights`.
