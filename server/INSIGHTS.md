## What Works
<!-- Approaches that proved effective here -->
- 2026-11-06 — Top-N-per-group in ONE Drizzle query (no N+1 per agent): inner select with `sql<number>\`row_number() over (partition by … order by ran_at desc, id desc)\`.as('rn')` wrapped `.as('ranked')`, outer select filters `lte(ranked.rn, n)`; the inner join to `agents` carries the second workspace filter and drops `agent_id`-null runs (src/modules/agents/repository.ts:176 → recentDoneRunSamples).

## What Doesn't Work
<!-- Dead ends and antipatterns — the most valuable section -->
- 2026-11-05 — `options.exclude` in .dependency-cruiser.cjs removes the module AND all edges to it, so `exclude: ^src/vendor/` silently killed `domain-shared-type-only` (a clean run looked green; caught by the PR #12 AI review) → for paths rules point AT use `doNotFollow`, and prove rules with `node scripts/check-architecture.mjs --self-test` (.dependency-cruiser.cjs → options.doNotFollow).
- 2026-11-05 — `POST /agents/:id/skills` used to link ANY skill uuid (only the agent was workspace-checked), i.e. cross-workspace links were possible → link tables must check BOTH sides' workspace; skill ids are now validated (404) and duplicates rejected (422) (src/modules/agents/service.ts:181 → assertWorkspaceSkills).
- 2026-11-07 — `z.array(X).safeParse(row.sources)` on a jsonb list fails as a whole, so ONE invalid entry (branch `0-cleanup` → issue #0 fails `.positive()`) silently emptied every intent source → read stored jsonb lists entry by entry and drop only the bad one (src/modules/intent/schemas.ts:35 → parseIntentSources).

- 2026-11-07 — Under `NODE_ENV=test` `@fastify/rate-limit` is not registered AT ALL (README:54 says only the "global" limit is off), so per-route `config: { rateLimit }` caps never fire in `.it` tests and no 429 is reachable there → a 429 test must build the app with `nodeEnv: 'production'` (src/app.ts:95 → rateLimit registration; plans/intent-reliability.md T3).
- 2026-11-07 — Only a model-call/parse failure is an intent derivation failure: `compute` wraps just `classify` in `DeriveError` (negative-cached 60 s + `saveFailure`); provider resolution (`deps.llm`) and the `saveDerived` write propagate as-is, are NOT negatively cached and NOT saved as failed, so a transient DB/config error doesn't block intent for the TTL → keep new steps outside that try unless they are the model call (src/modules/intent/service.ts:260 → compute, :316 → classify, :337 → persistDerived; test (e2) in test/intent-service.test.ts).
- 2026-11-07 — `repoIntel.getBlastRadius` is not what its types promise: the persistent path cuts `callers` to `MAX_CALLERS_PER_SYMBOL` for the WHOLE PR (not per symbol), returns `degraded: false` for a `partial` index, and the ripgrep fallback always says `reason: 'no_data'` (never `flag_off`/`index_failed`/`index_partial`) and has no `factsByFile`/crons → a consumer that needs an honest reason must combine it with `getIndexState()` + `config.repoIntelEnabled`; blast callers are direct only (`BFS_DEPTH` is used by critical paths, not blast) (src/modules/repo-intel/service.ts:220 → getBlastRadius, :315 → tryPersistentBlast, :386 → slice).
- 2026-11-08 — CORRECTION of 2026-11-07 entry (getBlastRadius global cap): the cap is now per (viaFile, viaSymbol) via `capCallersPerSymbol` on BOTH paths, callers carry `viaFile`, self-callers and unresolved `declFile` rows are dropped, and `callersOmitted` reports the cut; the `degraded`/`reason` caveats still hold → don't reintroduce a global `slice` (src/modules/repo-intel/service.ts:757 → capCallersPerSymbol, called at :291 ripgrep and :386 persistent).

## Tool & Library Notes
<!-- Dependency / tooling quirks -->
- 2026-11-04 — pgvector is enabled only by `runMigrations()` (`src/db/migrate.ts`), no migration .sql does it → migrate via `pnpm db:migrate`, never `drizzle-kit migrate`, or `vector(1536)` columns fail (src/db/migrate.ts:23 → runMigrations).
- 2026-11-04 — On Windows `pnpm <script>` can fail with "Access is denied" → call bins via node: `node node_modules/typescript/bin/tsc --noEmit -p tsconfig.json`, `node node_modules/vitest/vitest.mjs run --exclude '**/*.it.test.ts'`, `node node_modules/drizzle-kit/bin.cjs generate` (package.json → scripts).
- 2026-11-05 — dependency-cruiser 17 rejects `to: { circular: true, viaNot: { path: … } }` ("viaNot must be string") → use the string form `viaNot: '^src/platform/container\\.ts$'`; container.ts cycles are expected (services `import type { Container }`) (../.claude/skills/onion-architecture/depcruise-rules.cjs → no-circular).
- 2026-11-05 — dependency-cruiser's `--ignore-known` baseline matches RESOLVED paths; under pnpm those are `node_modules/.pnpm/drizzle-orm@<ver>_…/…/index.d.ts` → any dependency bump makes known violations "new". `preserveSymlinks` drops the version but not the entry file; `collapse` doesn't help (applied at report time, after known-violation matching — main/report-wrap.mjs) → match on normalized keys `rule|from|node_modules/<pkg>` instead (scripts/check-architecture.mjs → normalizeTarget).
- 2026-11-05 — `llm.completeStructured` without `maxTokens` reserves the model max (65k) → OpenRouter 402 "requires more credits" on low-limit keys before generating anything; always pass a cap for structured calls (src/modules/conventions/constants.ts:23).
- 2026-11-05 — drizzle-kit `generate` asks interactively "renamed or new?" when one run both adds and drops a column; split into two generates (add + backfill, then drop) — conventions `accepted` → `status` (src/db/migrations/0011_*, 0012_*).
- 2026-11-06 — Drizzle `onConflictDoUpdate({ setWhere })` + `.returning()` returns ZERO rows when `setWhere` blocks the update (it does not return the existing row) → after a guarded upsert, `get()` the row when `returning` is empty (src/modules/intent/repository.ts:172 → saveFailure).
- 2026-11-07 — `core.autocrlf=true` checks server sources out with CRLF, so a scripted mutation (Python `str.replace` on `"\n}\n"`) silently matched nothing, and the "mutated" RED run was green, which looked like a vacuous test → after applying a mutation, confirm it took (`git diff --stat <file>` non-empty) before reading the result; match on `\r?\n` or edit with the Edit tool (src/modules/intent/schemas.ts:35 → parseIntentSources, mutation check in plans/intent-reliability.md T5).
- 2026-11-07 — With `LOG_LEVEL=silent` `buildApp` passes `logger: false`, whose `child()` returns the SAME object, so `req.log === app.log` in tests: an assertion "logs on the request logger (with reqId), not app.log" passes vacuously (reverting `req.log.warn` → `app.log.warn` stayed green) → build that app with `LOG_LEVEL: 'warn'` (real pino), mock `app.log.warn/error`, and swap `req.log.warn` in an app-level `onRequest` hook (src/app.ts:50 → buildApp logger; test/app-rate-limit.test.ts:24 → warnConfig).
- 2026-11-07 — `src/adapters/depgraph/index.ts` contains a literal NUL byte (edge-dedup key separator `${from}\0${to}`), so the Read tool flags it as binary and Edit/Write refuse to modify it → change it with a byte-preserving node script (`fs.readFileSync` → string replace → `writeFileSync`), then confirm with `git diff` (src/adapters/depgraph/index.ts:93 → buildEdges key).
- 2026-11-08 — dependency-cruiser `cruise()` resolves against `process.cwd()`; on Windows an absolute root on a DIFFERENT drive than cwd (`os.tmpdir()` on C: while the repo is on F:) throws ENOENT, which `buildEdges` swallows → returns `[]` silently → create depgraph test fixtures under cwd (`mkdtemp(join(process.cwd(), '.depgraph-test-'))`), not in `tmpdir()`; a clone on another drive would also yield 0 edges (src/adapters/depgraph/index.ts:72 → cruise call in buildEdges; test/depgraph-paths.test.ts).
- 2026-11-08 — On Windows `POST /repos/:id/resync` can "succeed" silently: the job row ends `done` with no `error` while index-state never changes, because `git reset --hard origin/<branch>` fails on paths > 260 chars (clone path under `server/clones/…` is ~108 chars + client paths like `…/IntentCard/_components/IntentEditForm/IntentEditForm.tsx` = 270) without `core.longpaths`, and `resyncRepo` turns that into a degraded `sync_failed:` result that the job handler discards → check `git -C <clone> rev-parse HEAD` vs `origin/<branch>`; enable `core.longpaths true`; don't trust job `status = done` as proof of a resync (src/modules/repo-intel/service.ts:143 → resyncRepo, :179 → RESYNC_JOB_KIND handler; src/adapters/git/simple-git.ts:77 → sync).
- 2026-11-08 — A Bash-tool heredoc (`cat <<EOF` / `node -e` with `\u0000`) collapses escape sequences, so a script meant to write the 6-char text `\u0000` wrote a real NUL byte back → write any script containing backslash escapes with the Write tool into the scratchpad and run it with `node <file>`; then check bytes, e.g. `node -e "…filter(x=>x===0).length"` (src/adapters/depgraph/index.ts:94 → buildEdges key).
- 2026-11-08 — CORRECTION of 2026-11-07 entry (NUL byte in depgraph): the NUL byte is gone; the key is now the text escape `` `${from}\u0000${to}` `` and `toRel` normalizes to POSIX, so Read/Edit work on the file normally (src/adapters/depgraph/index.ts:94 → buildEdges key, :113 → toRel).
- 2026-11-08 — Postgres `order by` on text follows the DB locale: the dev DB (en_US) sorted `AGENTS.md` before `.claude/…` in `array_agg(distinct path order by path)`, while a JS `.sort()` in tests expects byte order, so a test passes or fails depending on the container's locale → when a sorted path list is part of a contract, use `collate "C"` in both the DISTINCT arg and the ORDER BY (src/modules/blast/repository.ts:48 → listPriorPulls sharedFiles).
- 2026-11-08 — `MockGitClient.readFile` returns `opts.files[path] ?? ''` and NEVER throws, so with it a deleted / unreadable file looks like an empty one and "missing file" paths (best-effort enrichment, `status: 'missing'`) are silently untested → in such tests subclass it (`class FakeGit extends MockGitClient { override async readFile … throw }`) or pass a fake `git` override whose readFile throws for unknown paths (src/adapters/mocks.ts:293 → MockGitClient.readFile; test/context-routes.it.test.ts → FakeGit).
