# Implementation Plan: Project Context — editable DevDigest docs

- **Status:** in progress
- **Execution mode:** multi-agent  <!-- user's choice -->
- **Goal:** Per repo, users create, upload, edit, copy and delete their own `.devdigest/specs/` docs inside DevDigest (never in the repo). These docs attach to agents and reach runs like repo docs. The Project Context page becomes the full-width N6 two-panel layout with a grouped tree and a typographic preview.
- **Specs:** `SPEC-03` — specs/project-context-editable-docs.md (approved; supersedes parts of `SPEC-01` — specs/project-context-folder.md; reuses `DocMarkdown` / `DocSourceBadge` from `SPEC-04` — plans/project-context-agent-tab-and-trace.md)
- **Packages:** server · client · e2e
- **Out of scope:**
  - (spec Non-goals) writing to the repo, its clone or GitHub; editing repo docs in place; N6 COVERAGE / chunk counts / embeddings; attaching docs to skills (SPEC-05); rename/move, version history, concurrent-edit warnings (last save wins); agent Context tab and trace presentation beyond what AC-11 requires (SPEC-04); `.devdigest` docs as Onboarding Tour input (SPEC-02).
  - Repo docs keep SPEC-01 discovery, the 4,000-token cap and the injection rules. `run-executor.ts` and reviewer-core are unchanged: `forRun` keeps its signature, and only its contents and the optional trace field change.
  - Responses of the existing `GET /repos/:id/context-docs` and `/content` keep their shape (`ContextDoc` gains only the `devdigest` source value). The new per-page data (`synced_at`, ignored count, doc ids) comes from the new `GET /repos/:id/devdigest-docs`. This way no SPEC-01/SPEC-04 client fixture breaks (technical decision, see Contracts).

## Global constraints

- No edits in `*/src/vendor/shared/**`. New API shapes live in `server/src/modules/context/domain.ts` (+ Zod in `schemas.ts`) and are mirrored in `client/src/lib/types.ts`.
- One migration, generated by `node node_modules/drizzle-kit/bin.cjs generate` in T0 (never hand-edited); it is the only migration task.
- Workspace scoping (security, AC-12): `devdigest_docs` HAS `workspace_id`, and every query on it filters by it. `agent_context_docs` reads/writes stay scoped through workspace-checked parents. Another workspace's repo or doc → `NotFoundError` (404), never 403.
- Doc bodies and uploaded file names are untrusted. Paths are names only (never a filesystem path). Content reaches prompts only through the existing engine `specs` slot (`wrapUntrusted`). The UI renders bodies with `DocMarkdown` (raw HTML as text) and names/paths as plain text.

- Client: no `fetch` in components (hooks only). All text comes from `messages/en/*.json` (T1 owns every key). Import only from the `@devdigest/ui` barrel. Use only existing CSS vars (`src/test/css-vars.test.ts`). Reuse `DocMarkdown` (`src/components/doc-markdown`) and `DocSourceBadge` (`src/components/doc-source-badge`) unchanged.

/**

 * Rules, checked in this order on the raw text: name === '' → empty; folder or name contains `..` → dot_dot;
 * `\` → backslash; name or a non-empty folder starts with '/' → leading_slash; \r or \n → line_break;
 * an '' or '.' segment in `${folder}/${name}` (folder '' adds no segment) → empty_segment.
 * appendMd: a name not ending in '.md' (case-insensitive) gets '.md'. Full path = DEVDIGEST_ROOT + rel;
 * length > MAX_DOC_PATH_CHARS → too_long.

## Risks · Review focus

- **Workspace scoping on the new table and routes** (T2, T6, T10): every `devdigest_docs` statement filters `workspace_id`, including the select inside the delete transaction, and `attachedAgents` joins `agents.workspace_id`. The T10 `.it` test hits all 7 routes from a second workspace and expects 404.
- **`.devdigest/` namespace leaks** (T0, T6): repo files under `.devdigest/` must never be discovered, read by `getDoc` or put into a prompt as repo docs, and devdigest paths must never reach `git.readFile`. `classifyDocPath`, `discover`, `getDoc` and `forRun` all branch on it, and T6 tests cover each.
- **Untrusted content and limits** (T0, T6, T7, T8): size is checked on decoded bytes before the UTF-8 decode, NUL/invalid UTF-8 → `not_text`, and the DB `size_check` is a backstop. The save route `bodyLimit` must exceed 1 MiB of JSON-escaped text, so that the service (not Fastify) gives the specific `too_large` reason; a 413 is still mapped to `too_large` client-side. The preview uses `DocMarkdown` only.
- **Cache consistency after mutations** (T3): create/copy must `setQueryData` the new doc before the view selects it. Delete must invalidate every agent's `agent-context-docs` (detached server-side), and save must refresh tokens in both lists (page tree + agent tab).
- **Unsaved-changes guard coverage** (T7, T11): selection, in-app links (capture-phase click) and reload (`beforeunload`) are guarded, and `DocPane` is keyed by path so a draft never leaks into another doc. Browser Back/Forward is not guarded (see Open questions).
